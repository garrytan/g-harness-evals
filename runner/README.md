# Runner: dispatch, metering proxy, budget ledger and price table

`runner/run.ts` plans a preregistered run and dispatches its trials. harness-evals v0.0.5: `run` drives multi-user trials end to end against the simulated company, the metering proxy and a harness speaking the `serve` protocol, and writes the evaluator-owned record of every trial; a cell that carries `gbrain` also gets a gbrain sidecar per trial (the gbrain arm, [docs/gbrain-arm.md](../docs/gbrain-arm.md)). The single-shot hello/smoke path from M0 still runs through the same command.

## Commands

```sh
bun runner/run.ts plan      --prereg docs/benchmarks/<run>/prereg.json [--out results/<run-id>]
bun runner/run.ts dry-run   --prereg <file>
bun runner/run.ts preflight --manifest results/<run-id>/manifest.json [--gbrain-image <tag>] [--gbrain-commit <sha>] [--cells a,b]
bun runner/run.ts run       --manifest results/<run-id>/manifest.json [options]
```

`plan` expands the preregistration into `manifest.json`: one preallocated trial id per cell, task and repetition, and the cost ceiling priced from the pinned price table. A run id is used once (HE-RUN-003). `dry-run` prints the same without writing.

A cell names `harness`, `model` (`provider:model`), `slice`, `split`, `repetitions` and a `ceiling` in tokens. For a multi-user cell the ceiling is per turn and a trial is priced as turns x ceiling, with the turn count read from each task's `task.toml`. Tasks come from `cell.tasks`, else `tasks.<slice>` in the preregistration, else every directory under `tasks/multiuser/[<task_set>/]<split>/`; `task_set` (default `v0.1`, the root; `v0.2` is `tasks/multiuser/v0.2/`) is printed on every multi-user cell line, an explicit list naming tasks the set does not hold is refused once with HE-PREREG-004, and a key outside the Cell interface is refused with HE-PREREG-007. `session_scope: "turn"` passes `HE_SESSION_SCOPE=turn` to the adapter (a fresh harness session per turn, the memoryless contrast; OpenClaw only, docs/adapters.md). `utility_models` lists the models the harness is documented to call for its own housekeeping beside the cell's model (QM's and OpenClaw's `claude-haiku-5-5` request per turn); HE-MODEL-001 treats them as the cell's own, the proxy forwards and prices them when the run's allowlist admits them, and the plan prints them on the cell line. Optional fields: `harness_mode` (`docker`, the default; `process`; `scripted`), `adapter` (process mode: the script to run), and for scripted cells `harness: "scripted"`, `model: "none"` and `script: "oracle"` or `"mutations"`, which expands to one trial per task's `oracle.json` or per `mutations/<predicate-id>.json`. Scripted cells cost nothing.

A cell may carry `"gbrain": { "surface": "starter" }`: every trial of that cell runs beside a gbrain sidecar and the harness registers a second MCP server named `gbrain` (docs/gbrain-arm.md). Only the pinned surface is accepted, and a scripted cell cannot carry it (HE-GBRAIN-001). `plan` and `dry-run` print `gbrain=starter` on the cell line and a `GBRAIN:` line naming the sidecar image; `preflight` checks the image exists and starts one sidecar to prove it serves `/health` (HE-GBRAIN-002 otherwise), leaving its files under `results/<run>/preflight-gbrain/`.

internal-task (member brain) adds `"brain": "member"` (the bot-visible slice in reader-set sources plus empty per-channel and per-member sources, member tokens and ingest tokens) and `"ingest": "live"` (member brain and member scope only, HE-GBRAIN-003 otherwise): the world writes every message posted during the trial into its conversation's source as a `remember` fact, flushed at every turn boundary and after the fence, a failed write ending the trial as HE-GBRAIN-011 (a conversation the brain has no source for is skipped and counted, not a fault), docker mode only (HE-GBRAIN-001 in process mode); `preflight` probes the member brain as it does the company brain, under member scope with live ingestion (docs/gbrain-arm.md, "The member brain and live ingestion"). The cell line shows `ingest=` when set. internal-task (company brain) adds two optional fields to `gbrain`: `"brain": "company"` serves the brain holding every record of the split instead of the bot-visible slice (`"bot-visible"`, the default), and `"scope": "member"` (company brain only; other values or a scope without the company brain are HE-GBRAIN-003) makes the world's tap present the requesting member's gbrain token instead of the trial's unscoped token, so the brain answers each turn as the member who asked. internal-task (gbrain#7481) adds `"scope": "sources"`: the tap keeps the unscoped token and sets `source_ids` on every `search` and `query` to the requesting member's granted sources from the company brain's `manifest.json` (public before the first turn), intersecting a harness-supplied list with the grant and denying an all-foreign one; HE-GBRAIN-004 when the grants do not cover an actor of the task; `preflight` probes every member's grant against the brain (docs/gbrain-arm.md, "The told-scoped rung"). The cell line shows `brain=` and `scope=` when set; `preflight` also starts the company brain for each split such cells use and, under the unscoped token, pages through `list_pages` until every page the build should hold (`gbrain/build-brain.ts` `companyPageList`) is listed, printing the count per kind, and under member scope also lists under one member token (nothing outside that member's reader sets) and under public-only (only pages every member may read), printing the image id and the member token count, so a scoped arm's leak counts are measured against a complete brain with working grants (HE-GBRAIN-002 when any check fails). `plan` prints a WARN line for a company-brain cell whose preamble is not the company one. A cell without the two fields is unchanged.

### `run` options

| Option | Meaning |
|---|---|
| `--harness-mode docker\|process\|scripted` | How non-scripted cells run (default `docker`). A scripted cell is always scripted. |
| `--adapter <script>` | Process mode: the adapter script (`.sh` under bash, `.ts` under bun) started with the argument `serve`. |
| `--image <tag>` | Docker mode: image instead of `harness-eval/<harness>:dev`. |
| `--gbrain-image <tag>` | Cells with `gbrain`: the sidecar image instead of `harness-eval/gbrain:dev`. The sidecar image is independent of `--image`: a harness image never carries gbrain. `preflight` requires the image's `/opt/sidecar/image.json` to record the gbrain commit `gbrain/pin.json` pins (HE-GBRAIN-002 otherwise), or the commit `--gbrain-commit <sha>` names, which `scripts/gbrain-check.ts` passes for the candidate it checks; it also refuses an installer view with no `installer.turn_hook` (HE-GBRAIN-006) while `gbrain/pin.json`'s `install.installer.turn_hook_expected` is true, except under `--gbrain-commit`. internal-task: the same image serves both surfaces, the keyword and the embedded brains and the install bundle; `preflight` checks the adapter in every harness image against the checkout (HE-ADAPTER-005), probes each distinct keyword configuration against the pinned tool count, probes each embedded configuration through the proxy under a $0.05 lease of its own (`<run_id>-preflight`, HE-GBRAIN-005 if no embedding line is forwarded or the reply is degraded) and exports and verifies every gbrain-docs cell's bundle view into `results/<run>/gbrain-install/<harness>/<split>` (HE-GBRAIN-006). |
| `--resume` | Skip trials that already have a line in `trials.jsonl`. Without it a run directory that holds trials is refused (HE-RUN-003). |
| `--stop-on-cap` | Stop at the first proxy lease refusal and exit 3; the default records the trial and continues. |
| `--cells a,b` | Only these cells. |
| `--ledger <file>`, `--lease-usd <n>`, `--new-lease` | The proxy's lease ledger (default `results/<run>/ledger.sqlite`), the lease (default the preregistered cap) and the proxy's `--new-run` for a ledger whose open lease belongs to another run id. |
| `--max-output-tokens <n>` | The proxy's output cap (Hermes needs 128000; TODOS). |
| `--preamble <file>` | Instead of `tasks/multiuser/_shared/preamble.md`. |
| `--ready-timeout-s <n>`, `--turn-grace-s <n>` | Defaults 180 and 60: how long to wait for `$HE_LOG_DIR/ready`, and how long past `time_budget_s` a turn may run before the harness is killed. |
| `--harness-env K=V` | Extra environment for the harness (debugging a harness; never a key). |

Exit 0 when every selected trial was recorded, 3 after a cap stop with `--stop-on-cap` (HE-BUDGET-001 on stderr), 2 on any HE- refusal.

## What one multi-user trial does

1. **World.** The simulated company starts in-process (`world/services/server.ts`) on a random free port, bound to every interface in docker mode so a container reaches it through `host.docker.internal`, with the task's split and actors; `trial.json` and `events.jsonl` land in the trial directory.
2. **Proxy slot.** The run's metering proxy binds a slot named after the trial to the trial token `trial-token:<id>` (`runner/trial/proxy.ts` `trialKey`); the harness's `HE_MODEL_BASE_URL` is `<proxy>/<slot>/<provider>` and its `HE_MODEL_API_KEY` is that token. The token is the trial id behind a fixed prefix, never a credential; it is recorded as `meter_id` in `usage.json` and `reconcile.json` and as `key` on the proxy's usage lines. Runs before 2026-10-26 minted `sk-trial-<id>` and recorded it under `key` in both receipts; those committed receipts keep the old shape (`scripts/reconcile-provider.ts` reads both; `scripts/publish-audit.ts` allowlists the old one, the new one matches no key shape) and the shape changed because secret scanners read an `sk-` prefix, or a `key` field with an entropic value, as a credential.
   **gbrain sidecar** (cells with `gbrain`, `runner/trial/gbrain.ts`): one container from the sidecar image on its own docker network with its MCP port published on the host loopback only, `HE_GBRAIN_SPLIT` the cell split and `HE_GBRAIN_OUT` mounted from `<trial dir>/gbrain/`; the runner waits for `/health` and the token file (60 s, HE-GBRAIN-002), points the world's `/gbrain` tap at it, and hands the harness `HE_GBRAIN_MCP_URL = <world>/gbrain` and `HE_GBRAIN_MCP_TOKEN = the world bot token`. The harness never sees the sidecar's token or address. internal-task: the cell's `brain` and `scope` go to the sidecar as `HE_GBRAIN_BRAIN` and `HE_GBRAIN_SCOPE`; under member scope the runner also waits for `<trial dir>/gbrain/tokens.json`, checks it is for the split and names a token for every actor of the task (HE-GBRAIN-004, before the harness starts), hands the tokens to the tap, names the requesting member to the world (`POST /admin/gbrain/requester`) at each turn's start before the turn window opens, so the setting holds through `wait_s` until the next turn, and clears it after the last turn. The token files never leave `<trial dir>/gbrain/`.
3. **Harness.** Docker: `docker run -d` with `/workspace`, `/harness-state`, `/he-logs` and `/he-turns` mounted, the `serve` environment table of docs/adapters.md, entrypoint argument `serve`; a harness with `compose.yaml` runs its stack with an override file that switches the task service to `serve`, after `prepare.sh` and before `capture.sh`, as `harnesses/run-trial.sh` does. Process: the adapter script on this host with the same variables pointing at host directories. Scripted: the in-process executor (`runner/scripted/executor.ts`), ready at once. The runner waits for `$HE_LOG_DIR/ready` (HE-ADAPTER-002 past the timeout).
4. **Turns.** For each turn in `task.toml`: advance the clock if asked (`POST /clock/advance`), post the actor's message through the Slack mock with that actor's token (`chat.postMessage` to the channel by name, or `conversations.open` with the bot and then post for a DM), compose the prompt from the preamble, write `turn-NNNN.request.json`, wait for `turn-NNNN.response.json` up to `time_budget_s` plus the grace (then kill the harness and record exit 124), post `reply_text` as the bot into the same channel, record a `TurnWindow` whose `started_seq` and `ended_seq` bracket the harness's work, then honour `wait_s`. The bot reply is posted after `ended_seq`, so it is never counted as the harness's own read.
5. **End.** `POST /admin/fence`, `GET /admin/snapshot` to `snapshot.json`, stop the harness (SIGTERM, 60 s, SIGKILL; compose: `capture.sh`, then `down -v`), stop the gbrain sidecar when there is one (after the fence, so no call lands in the brain unrecorded), finalize the proxy key into `usage.json` and `reconcile.json`, grade with `gradeTrial(TrialEvidence)` from `runner/grade/index.ts` (HE-GRADE-001 when absent), append the line to `trials.jsonl`.

Termination comes from the turn exits: all 0 is `completed` (or `approval_stop` when the grader says so); any 124 is `timeout`; else any 3 is `model_error`; else any 2 is `harness_error`. A harness that never wrote `ready` is `harness_error` or `model_error` when it exited 2 or 3 first, else `infra_error`. A proxy lease refusal during the trial makes it `model_error` with `cap_stop: true`. A world refusal of an actor's message (channel missing, actor not a member) is `exam_fault`.

## Results tree

```
results/<run-id>/
  manifest.json              from plan
  trials.jsonl               one TrialRecord per finished trial, appended atomically; --resume reads it
  run.log, run-summary.json  the runner's own log and the completion summary
  ledger.sqlite              the proxy's lease ledger (unless --ledger); proxy-usage.ndjson, proxy.log
  trials/<cell>/<task>/[<oracle|mut-<id>>/]r<n>/
    trial.json               tokens and MCP config (evaluator-owned; the redaction set)
    events.jsonl             the world's event log
    turns.jsonl              one TurnWindow per turn run
    turns/                   turn-NNNN.request.json and .response.json
    snapshot.json            GET /admin/snapshot after the fence
    usage.json, reconcile.json   the proxy meter for trial-token:<id> (field meter_id) and its check against the usage lines
    grade.json               GradeResult
    workspace/, state/, logs/    the harness's mounts; logs/ready, adapter.log, docker.log or harness.std*.log
    gbrain/                  gbrain cells only: token (the sidecar's bearer token, mode 0600), sidecar.log, serve.log, docker.log; under member scope also tokens.json, under scope sources
                             or live ingestion manifest.json, and under live ingestion ingest-tokens.json (mode 0600); never committed
```

The results `.gitignore` copied per run (`docs/benchmarks/2026-10-25-company-brain/results/.gitignore` for a run with a brain; it also ignores `preflight-*/`, which holds the preflight sidecar's tokens) excludes `trials/*/*/*/gbrain/` beside the harness state and `trial.json`, because the sidecar token lives there. A sharded run's merge (`scripts/merge-shards.ts`) copies each shard's preflight directory as `<shard>.preflight-*/`, so that run's `.gitignore` ignores `*preflight-*/` too; the merge itself never copies the sidecar's `token`, `tokens.json` or `ingest-tokens.json`, whatever the ignore file says.

### trials.jsonl fields (`TrialRecord` in runner/contracts.ts)

| Field | Meaning |
|---|---|
| `trial_id`, `cell`, `task`, `harness`, `harness_mode`, `model`, `script` | identity; `script` is the Script path for a scripted trial |
| `termination` | `completed`, `timeout`, `approval_stop`, `harness_error`, `model_error`, `infra_error`, `exam_fault` |
| `grade`, `consent_violation`, `approval_stop`, `effects`, `predicates` | the grader's verdict, kept apart from termination (methodology item 9) |
| `cap_stop` | the proxy refused a call because the lease or program cap was spent |
| `turns` | `planned`, `run`, and the exit of every turn run |
| `usage` | requests, refused, failed, usd, tokens in, out and cached, by model, upstream status counts; null for scripted trials |
| `wall_ms`, `started_at`, `ended_at`, `paths`, `error` | timing, where the files are, and the HE- line that cut the trial short, if one did |
| `gbrain` | cells with `gbrain` only: `surface`, `image`, `sidecar_ready_ms`, and `events` counting the trial's `via: "gbrain"` events (`total`, `discovery` for `initialize` and `tools/list`, `calls`, `in_turn_calls` inside a turn window, `writes`). The events themselves are in `events.jsonl`. internal-task adds `brain`, `scope` and `image_id` (the sha256 id behind the image tag); records written before it lack them. internal-task adds `ingest` and `ingested` (`{ok, skipped, failed}` counts of the trial's `gbrain.ingest` events; skipped is a conversation the brain has no source or token for, not a fault) on cells with live ingestion. |

`reconcile.json` checks the proxy's meter against the usage lines it wrote for the key; its `provider_reconciliation` line predates the run-level check and still says the provider check is not built. The run-level check is `scripts/reconcile-provider.ts` (below), which writes `results/spend-reconciliation.json`; per-trial files of a counted run are not rewritten.

## Sharded runs (internal-task)

A paid run longer than about four hours is sharded by whole cells across machines (CREW.md, "Parallelism"): every shard is a clean checkout at the preregistration commit, builds its images from it, holds one lease under the run's cap and runs its trials sequentially, and the preregistration names the shards. `scripts/run-shard.sh --prereg <file> --name <shard> --cells a,b --lease-usd <n> [--embedded] [--gbrain-image <tag>] [--out results/<run-id>] [--skip-build] [--resume]` does one shard: it refuses a dirty checkout, builds `harness-eval/<harness>:dev` for the harnesses its cells use and the gbrain image (`--embedded` for a shard with an embedded cell), runs `plan` (once), `preflight` and `run --cells ... --lease-usd ... --max-output-tokens 128000`, prunes graded trials' harness caches (`state/.cache`, `state/hermes/{bin,cache,skills,models_dev_cache.json}`) every five minutes, and writes `<out>/shard.json` (name, machine, commit, cells, lease, image ids, exit). `scripts/merge-shards.ts` merges the shard directories into one results directory with `shards.json` before `summarize-run` and `compare-run`. After gbrain-ladder-2026-10 (internal-task): `preflight --cells a,b` scopes its checks to one shard's cells, so a shard builds only the harness images and gbrain configuration its cells need; `run-shard.sh --resume` keeps `shard.json` as the record of the first launch and appends to its `resumes` list, refuses a HEAD other than the recorded commit unless `--amendment <commit>` names it, and skips preflight when `preflight.log` already says `PREFLIGHT: ok`, because the preflight lease is closed in the ledger and a closed lease is never reopened (HE-PROXY-003). From 2026-10-25 (internal-task) a counted run's shards run on ephemeral Ubicloud VMs, one standard-16 VM per shard through `scripts/ubicloud/run-shard.sh` and `scripts/ubicloud/fanout.sh`, which wrap this script and copy each shard's results tree back for `merge-shards.ts` ([docs/ubicloud.md](../docs/ubicloud.md)); the Capy machine path stays for one-off reruns.

## Harness modes

- **docker** is the counted configuration: the harness image and the mounts of docs/adapters.md. Everything docker-specific is in `runner/trial/docker.ts` (and `runner/trial/gbrain.ts` for the sidecar); nothing else needs a daemon. A gbrain cell in process mode still starts the sidecar container, so process mode needs a daemon for such a cell; a gbrain cell in scripted mode is refused (HE-GBRAIN-001), as is a live-ingestion cell (`gbrain.ingest: "live"`, internal-task) in process mode, where the harness process could read the ingest tokens under the trial directory.
- **process** runs an adapter script on this host for keyless tests: `tests/fixtures/serve-adapter.ts` honours the queue protocol with markers in the message text for sleeps, exits, a cross-scope read and a leak. `tests/trial-loop.test.ts` runs the whole loop this way with a stub grader.
- **scripted** plays an oracle or mutation (`Script`) as the bot over world-MCP with no harness, through the same turn loop, fence, snapshot and grader. This is how CI runs the oracle and mutation matrix through the real runner.

## Vendored pieces

Vendored from [gbrain-evals](https://github.com/garrytan/gbrain-evals) v0.10.128 (`6999ebc9`) and [gbrain](https://github.com/garrytan/gbrain) (`src/core/model-pricing.ts`, `embedding-pricing.ts`, `model-id.ts`), both MIT. Changes: import paths, `sanitize.ts` reduced to the leak tripwire the proxy uses, and a `cached_tokens` field on the proxy's usage lines.

- `proxy/metering-proxy.ts`: the only network exit for a harness container's model calls. In lease mode it strips inbound credentials and injects the real key from its own environment, allows only listed provider routes and priced models, bounds input tokens by request bytes, injects or enforces an output-token cap, reserves the worst case in the ledger before forwarding (concurrent requests serialize on the ledger), meters streamed responses from their usage events, refuses bodies carrying a forbidden marker, and appends one usage line per request (never a body or a key). Per-trial attribution: the runner binds a slot (the path segment the container's base URL carries) to a trial key with `POST /__proxy/bind {slot, key}`, reads the meter with `POST /__proxy/finalize {key}` and releases the slot with `POST /__proxy/unbind {slot}`; with `--control-token` these need the `x-proxy-control` header, so a container cannot move charges. The runner starts one proxy per run (`runner/trial/proxy.ts`) with the manifest's models as the allowlist; the proxy's environment is the only place a provider key lives.
- `ledger/budget-ledger.ts`: SQLite ledger (WAL, synchronous=FULL). Reserve before dispatch, settle to provider usage, cap recorded in the ledger with who set it and why, refusals name the fix. `docs/budget-ledger.md` in gbrain-evals describes the operator commands; the same CLI works here as `bun runner/ledger/budget-ledger.ts`. The program ledger for this evaluation lives outside the repository (the project drive, `harness-eval/ledger/program-ledger.sqlite`); its recorded cap is $2,000 (plan D10, set 2026-10-22), and every paid run opens its lease in it.
- `contracts.ts`: the shapes the runner, the adapters (`TurnRequest`, `TurnResponse`), the graders (`TrialEvidence`, `GradeResult`), the scripted oracle and mutation solutions (`Script`) and the trial record (`TrialRecord`, `TrialUsage`) agree on. See docs/tasks.md and docs/adapters.md.
- `pricing/`: the list-price table (`canonicalLookup`). A model with no row cannot be reserved and so cannot run (HE-PIN-002). Register a price before a cell runs, in the same commit as the preregistration amendment that adds the model.

What the plan still asks for on top of this (TODOS): egress enforcement, forced `stream_options.include_usage` on OpenAI chat streams, native Anthropic Messages and OpenAI Responses metering fixtures for the Claude Code and Codex cells, and per-run external reconciliation against the provider usage page.

## Report tooling (gbrain arm, lane E)

The scripts that turn `results/<run>/trials.jsonl` into report tables, all keyless, all writing their JSON beside the trials file: `bun scripts/summarize-run.ts --results <dir>` prints the per-cell table (trials that ended as `model_error`, `infra_error` or `exam_fault` leave the scored rows and denominators and are counted in the Excluded column, methodology item 9; their spend stays), the per-task pass table, a per-cell x family table with task counts (families read through each manifest cell's `task_set`), a table of secondary predicates (`predicates.secondary`, with their capability: passes over trials carrying the predicate, and the same among trials that passed the task, so a pass can be read as "recalled without re-reading" or "recovered by re-reading") and the failed-predicate counts, and writes `summary.json` with `families` and `secondary` keys; it also reads each trial's `events.jsonl` and adds a `gbrain` block per cell (trials with at least one gbrain tools/call, trials that listed the tools, calls per trial as median and total, the histogram of gbrain tools, pages returned per call and latency medians, errors, writes, and cross-scope reads that came via gbrain against via the world), zeros for a cell without gbrain, with `events_read` saying how many logs it found; internal-task adds to that block `scope_leaks` (the offending gbrain reads named by `no_cross_scope_reads`, as `search_rows` for unreadable rows `search` and `query` returned, `opened_returned` and `opened_refused` for unreadable pages a targeted read obtained or was refused, each by page kind, and `by_grant` for all of them by the grant the event carries), `pages_by_kind` and `unmapped_slugs`, with a second gbrain table printed when any cell has an offending read or an unmapped slug; a nonzero unmapped count is marked, because that cell's leak counts may not be published until every slug its brain returned maps to a world record. internal-task adds a top-level `ingest` key with a block per cell whose records carry `gbrain.ingest` "live" (no block for any other cell), printed as a "Live ingestion" table: ingestion counts per trial from `gbrain.ingested` (ok, skipped, failed: median and total), the write latency from the `gbrain.ingest` events (median, p90, max; a skipped message made no write and is left out), facts returned per `search`, `query` or `recall` call (median, max, the share of calls returning at least one) and the distinct `args.query` strings those calls sent with counts, the top ten per cell. `bun scripts/compare-run.ts --results <dir> [--families ...]` is the pairwise harness comparison and `--against <other run>` the across-run model effect; `--pair gbrain` is the within-run gbrain arm: for each (harness, config, model) it pairs the cell with gbrain (a truthy `gbrain` field in the manifest cell, or a `gbrain` segment in its id) against the cell without, trial by trial on the same task and repetition index, over the four capable families and over all tasks, excluding a pair whose trial ended as `model_error`, `infra_error` or `exam_fault` on either side and publishing the count, with Holm across the harness pairs of one model, and writes `comparisons.gbrain.json` (passed counts, gbrain minus none with its task-clustered interval, the per-task table, discordant counts, Holm-adjusted p, and median USD and seconds per trial and total input tokens for both cells); for gbrain-memory-2026-10 (its preregistration's Endpoints item 1) each entry of the arm's `excluded` array carries the pair's task, the side that dropped it (none, gbrain or both), the reason and the harness's gbrain call count on that side (`gbrain.events.calls`, null without a gbrain block), printed as an "Excluded pairs" table under each scope, and the primary scope carries one preregistered sensitivity row per pair, `sensitivity.faults_as_failures`, the same estimate with the gbrain cell's HE-GBRAIN-011 exam faults counted as live failures instead of excluded (the none side at its real value), with the number of pairs it re-included and its own Holm family; with no faulted pair it equals the main estimate and says so. `bun scripts/paired-mdd.ts --results <dir>` prints the minimum detectable difference of that paired design from an existing run's per-task pass rates, under the null that gbrain changes nothing and with the two arms independent given the task, beside the sign-flip bar of the preregistration (six task clusters all one way). `bun scripts/regrade.ts --results <dir>` re-reads every trial's evidence with the grader at the current commit into `trials.regraded.jsonl`, which `--regraded` on the two scripts above consumes. `bun scripts/secondary-endpoints.ts --results <dir> [--seed N] [--draws N] [--families a,b]` (internal-task, v02-heldout-2026-10) computes the preregistered secondary endpoints of a gbrain-told against none arm with the same pairing and estimator as `compare-run --pair gbrain`: cross-scope reads by any route, cross-scope reads via gbrain, hidden-fact leaks, consent violations, and pass over the continuity family alone, Holm within one model per endpoint; it writes `secondary-endpoints.json` beside `trials.jsonl` and prints the Markdown tables. gbrain-memory-2026-10 adds `cross_scope_fact` (a `no_cross_scope_reads` failure whose evidence carries the grader's "fact #<id> was ingested from" line, a returned fact mapped through a `gbrain.ingest` event to a conversation the requester is not in) in the same Holm family as the others, and `cross_scope_gbrain` now matches only the grader's `seq=<n> gbrain.<tool>` read lines (before, any evidence containing the word gbrain, including the grader's trailing "ignored for scope" note about a harness's own unmapped pages or facts; a fact-read line starts the same way, so `cross_scope_fact` is a subset of it), unchanged on v02-heldout's figures. Tests: `tests/scripts-gbrain.test.ts`.

**The install ladder (internal-task).** The same three scripts read the ladder's records (docs/gbrain-arm.md, "The install ladder"). `summarize-run.ts` adds a top-level `ladder` key per cell to `summary.json` and prints an "Install ladder" table when any trial carries a `gbrain` record: the harness's own input tokens per trial (median and total; the runner keeps the sidecar's `/v1/embeddings` lines out of this figure), the sidecar's embedding usage summed from `gbrain.embedding_usage` (requests, input tokens, USD, refused, failed, trials with usage), the install bundle from `gbrain.install_bundle` (file count, view digest, and for Hermes the largest number of compiled-context pages outside an actor's scope), the semantic exclusions (`gbrain.semantic_check.ok` false, HE-GBRAIN-005) and the degraded calls (`gbrain.events.degraded`); every existing key and table is unchanged. `compare-run.ts --pair gbrain` reads each cell's rung from its resolved gbrain configuration and preamble (`scripts/gbrain-ladder.ts`: no gbrain is `none`; a preamble other than the default makes a told rung; a configuration on no rung, such as a company brain, is a refusal naming the cell) and pairs each rung against its ladder neighbour within harness and model: mcp against none, told and docs against mcp, verbs-told and semantic-told against told, docs-semantic against docs. A rung whose base cell is absent exits 2 naming the cells. Three endpoints, each 1 or 0 per trial: pass, gbrain use (`gbrain.events.calls` above zero) and a cross-scope read via gbrain (the `no_cross_scope_reads` evidence names a gbrain read), through the same trial-by-trial pairing and task-clustered estimator as the arm, over the four capable families and over all tasks. Holm runs per endpoint over the comparisons of one harness on one model: six for pass; five for use and cross-scope, where mcp against none has no test (the none cell is 0 by construction) and is reported as the mcp cell's rate with its task-clustered interval. The none table is descriptive: every rung against the none cell, intervals and no test. Cost per trial, wall per turn and the harness's input tokens are paired differences (rung minus base, mean over pairs) with task-clustered intervals over all tasks. The design is chosen from the manifest (any verbs, gbrain-docs or embedded cell is the ladder, otherwise the arm) and `--design arm|ladder` overrides it; `comparisons.gbrain.json` says which with `design`. `paired-mdd.ts --ladder` prints the minimum detectable difference per endpoint for the ladder's design (20 tasks by 5 repetitions) with the receipt path of the rates it used: the gbrain arm's Haiku trials from `docs/benchmarks/2026-10-24-gbrain-arm/results` (or `--results`) once committed, else the committed Haiku sensitivity run for pass (11.5 points for OpenClaw, 10.3 for Hermes, at alpha 0.05 and power 0.8) and a stated assumption for use and cross-scope (every task at one rate; 20.3 points at 0.5, the widest a binary endpoint gets), each row labelled measured or assumption.

**Sharded runs: `merge-shards.ts` and `shards.json`.** A run longer than about four hours is sharded by whole cells across machines, each shard a clean checkout at the same commit that runs `plan` itself, trials sequential within a shard (CREW.md, Parallelism). `bun scripts/merge-shards.ts --out <results dir> --shard <name>=<shard results dir> [--shard ...]` builds the merged directory the report scripts read, and refuses (exit 2, naming the offender) rather than guessing: `trials.jsonl` is every shard's records in the manifest's trial order (a trial id in two shards, a manifest trial in no shard, or a trial no manifest planned is a refusal; a shard that stopped short is finished with `run --resume` first); `trials/` holds each shard's trial directories (a cell directory in two shards is a refusal); the first shard's `manifest.json` is kept and every other shard's must agree with it once `created_at` is removed (run id, preregistration sha256, cells, trials, ceilings), each kept as `<name>.manifest.json`; each shard's own files go under its name, `<name>.ledger.sqlite`, `<name>.proxy.log`, `<name>.proxy-usage.ndjson`, `<name>.run-summary.json`, `<name>.run.log`, `<name>.reconcile*.json`, `<name>.preflight-*/`, `<name>.gbrain-install/` and `<name>.shard.json`; and `shards.json` is written as `{ cells: { <cell id>: <shard name> }, shards: { <name>: { machine, commit, images, source, trials, cells } } }`, with `machine`, `commit` and `images` from the shard directory's `shard.json` (`{name, machine, commit, images}`, written by whoever dispatched the shard; a name that is not the `--shard` name is a refusal) and null without one. Nothing is written until every check passes, and an `--out` that already holds `trials.jsonl` is refused. `compare-run.ts --pair gbrain` reads `shards.json` when present and labels every cost and latency row "same machine (<shard>[ on <machine>])", "different machines (<a>, <b>)" or "shard unknown for <cell>", and "shards unknown (no shards.json)" without the file, because wall time measured on two machines is confounded with the machine; a reader should weigh a latency difference across shards accordingly.

**Spend reconciliation (internal-task).** `bun scripts/reconcile-provider.ts --results <dir> [--results <dir> ...] [--write] [--api-key-id <apikey_...>]` sums a run's priced proxy lines per UTC day and model, cross-checks them against `trials.jsonl` and the lease ledger (a difference over a cent is reported and exits 1), prints the per-day sheet in the console's shape, and, with `ANTHROPIC_ADMIN_KEY` in the environment, fetches the Admin API's usage report (by model and api key) and cost report for the span and compares them with the proxy totals pooled per day across every run given, because runs that share a day and a key are one bucket to the provider; the verdict is a relative residual per day and model against the 1% bar with a status (`performed`, `performed_mismatch`, `performed_unattributed` without `--api-key-id`, `performed_no_data`, `not_performed`), a day that ended less than 24 hours before the fetch left out. `--write` saves `results/spend-reconciliation.json` (the sheet, the cross-check, the provider rows for the chosen key only, and the labelled `provider_reconciliation` line); `--provider-fixture` replays a recorded response for tests and refuses `--write`. Every byte out passes a tripwire against the key value and a redaction of key-shaped strings. HE-RECONCILE-001 to 004 in docs/errors.md.
