I set up a free local brain with no API keys and connected it to OpenClaw. One piece isn't working yet: the plugin that reminds the agent to check gbrain on each message isn't running. It needs a gateway restart, and I couldn't trigger one from here.

**What I set up**
- **Brain:** created with `gbrain init --pglite --no-embedding`. It's a built-in local database with embeddings turned off, so nothing leaves this machine and nothing costs money. Search matches keywords only (no meaning-based search), which is the trade-off for staying keyless. `gbrain doctor` reports health 90/100 with all checks OK. The lower "brain score" is just because there are no embeddings and almost no content yet.
- **Settings:** I kept gbrain's defaults:
  - Search mode is conservative.
  - Agents only save facts when asked.
  - Free background upkeep is on.
  - A redacted daily conversation archive is on. Turn it off with `gbrain transcripts archive off`.
- **Test memory:** saving and finding a test fact ("gbrain install check") worked. I left the fact in the brain because gbrain warns that deleting a fact saved without an entity blocks it from being saved again.

**Connecting it to OpenClaw**
- **gbrain tools in OpenClaw:** registered the `gbrain` MCP server under `mcp.servers.gbrain`, pointing at `/harness-state/.bun/bin/gbrain serve --surface starter --advertise verbs`. I started that command directly and it lists its tools (remember, recall, entity, forget and others). OpenClaw said the change applies without a restart.
- **Instructions:** `gbrain setup openclaw` created `/workspace/AGENTS.md` with a short "check GBrain first" section. New sessions will read it.
- **Not working yet:** the per-message reminder plugin `gbrain-turn-rule` is installed and enabled, but its hook hasn't loaded. gbrain setup confirmed this with a `turn_hook_not_loaded` error. My restart attempt failed: OpenClaw asked for a new conversation, and the plugin reload needs a running gateway, which this environment doesn't have (`openclaw status` shows it unreachable). It should load the next time the gateway starts; nothing else needs fixing. Until then, the `AGENTS.md` instructions are what tell new sessions to use gbrain.

**Other changes**
- I created `~/.bashrc` to add `~/.bun/bin` to the command search path, so `gbrain` now works by name in new shells.

Start a new session to pick up the gbrain tools and instructions. After the gateway's next start, you can check the reminder plugin with `openclaw plugins inspect gbrain-turn-rule --runtime --json`: `hookNames` should include `before_prompt_build`.
