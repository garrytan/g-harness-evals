**Search mode: `conservative` is in effect.** It was picked automatically because there's no chat key and no reranker. You can change it at any time:

```
Estimated downstream input cost of the retrieved payload @ 10K queries/mo:

                  Haiku 5.5     Sonnet 5.5    Opus 5.5
                  ($0.10/M in)  ($2/M in)     ($4/M in)
  conservative    $4/mo         $80/mo        $160/mo
  balanced        $10/mo        $200/mo       $400/mo
  tokenmax        $20/mo        $400/mo       $800/mo

  Assumed payload per query: conservative 4K, balanced 10K, tokenmax 20K tokens.
  Scales linearly: x10 for 100K queries/mo, /10 for 1K. 200x corner-to-corner spread.
  Embedding, reranking and query expansion are separate provider charges.
```

1. **conservative** (current): a tight 4K budget with at most 10 chunks and no reranker. Best for Haiku subagents, cost-sensitive setups and high-volume loops.
2. **balanced**: a 12K budget with 25 chunks, reranked.
3. **tokenmax**: no budget, with 50 chunks, reranked. It gives the widest retrieval and is recommended once a chat key is set.

The reranker in balanced and tokenmax needs a provider key, so on this keyless brain they can't rerank. Query expansion is off in every mode by default. To switch, run `gbrain config set search.mode <mode>` (check with `gbrain search modes`). You can also turn on automatic saving of facts you state (`salient`, the recommended setting) or add starter pages for a personal or company brain whenever you like.
