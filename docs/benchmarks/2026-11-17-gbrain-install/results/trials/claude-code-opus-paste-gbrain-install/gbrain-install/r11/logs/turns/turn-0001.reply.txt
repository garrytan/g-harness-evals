**Search mode: `conservative`, picked automatically** because there's no chat key and no reranker. It controls how much retrieved text goes to the model, and you can change it any time:

```
Estimated downstream input cost of the retrieved payload @ 10K queries/mo:

                  Haiku 5.5     Sonnet 5.5    Opus 5.5
                  ($0.10/M in)  ($2/M in)     ($4/M in)
  conservative    $4/mo         $80/mo        $160/mo
  balanced        $10/mo        $200/mo       $400/mo
  tokenmax        $20/mo        $400/mo       $800/mo

  Assumed payload per query: conservative 4K, balanced 10K, tokenmax 20K tokens.
  Scales linearly: x10 for 100K queries/mo, /10 for 1K. 200x corner-to-corner spread.
  Embedding, reranking and query expansion are separate provider charges.
```

1. **conservative** (in effect): a tight 4K budget, at most 10 chunks, no reranker. Best for Haiku subagents, cost-sensitive setups and high-volume loops.
2. **balanced**: a 12K budget, 25 chunks, reranked.
3. **tokenmax** (recommended once you add a chat key): no budget, 50 chunks, reranked. This is the widest retrieval.

To switch, run `gbrain config set search.mode <mode>`. Without an API key, the reranker that balanced and tokenmax use can't run. Queries are never expanded unless you pass `--expand` or run `gbrain config set search.expansion true`.
