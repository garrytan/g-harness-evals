**Blocked: the per-turn reminder plugin**
gbrain's docs say `AGENTS.md` alone is followed much less reliably than this plugin, which repeats the rule next to every message. Setup already wrote it to `/harness-state/openclaw/gbrain/gbrain-turn-rule`. I read its code: it only adds a fixed text reminder before each turn and reads and calls nothing. OpenClaw's managed setup won't install plugins from a local folder. Its other route, packaging the plugin into an archive, also failed, because OpenClaw doesn't support that for a plugin like this one. I didn't work around that by running the install commands myself. To install it, run:
```
openclaw plugins install --link /harness-state/openclaw/gbrain/gbrain-turn-rule --force --accept-capabilities
openclaw plugins enable gbrain-turn-rule
openclaw config set plugins.entries.gbrain-turn-rule.hooks.allowConversationAccess true
```
Then restart the gateway and check that it loaded with `openclaw plugins inspect gbrain-turn-rule --runtime --json`.

**Settings now in effect (gbrain's defaults)**
- **Search mode:** conservative, which keeps results small. Change it with `gbrain config set search.mode balanced|tokenmax`.
- **Automatic saving:** off, so agents save only what you ask them to remember. gbrain recommends `salient`, which saves important facts you state: `gbrain config set memory.auto_writeback salient`.
- **Free background upkeep:** on while an agent is using gbrain. Turn it off with `gbrain config set maintenance.auto false`.
- **Conversation archive:** on. It keeps one redacted page per conversation per day, stored locally. Turn it off with `gbrain transcripts archive off`.

To add existing notes later, run `gbrain import <dir> --no-embed`.
