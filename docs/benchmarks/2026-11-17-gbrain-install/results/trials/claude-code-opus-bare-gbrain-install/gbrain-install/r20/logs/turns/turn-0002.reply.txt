gbrain is set up for Claude Code as a free local brain with no API keys. I saved a test fact and recalled it, and Claude Code shows the gbrain server as connected. It takes effect in your next Claude Code session; type `/mcp` there to see gbrain listed.

**Where things are:**
- **Brain:** `~/.gbrain/brain.pglite`, a local database that needs no server.
- **Claude Code:** gbrain was added to `~/.claude.json` and two hooks went into `settings.json`: one runs when a session starts and one on each prompt. A new `CLAUDE.md` tells Claude to check the brain first. All three are in `/harness-state/claude/`.
- **Test fact:** the recall test left one fact in the brain: "gbrain v0.60.734.0 was installed on this machine on 2026-11-17". It's accurate, so I kept it.

**Settings now in effect (all setup defaults, all free):**
- **Search mode:** conservative, which is keyword search only since there are no embeddings.
- **Saving facts:** agents save only what you ask them to remember. Run `gbrain config set memory.auto_writeback salient` to have them save lasting facts you state; gbrain recommends this for a personal brain.
- **Automatic capture:** off. No conversation transcripts are saved by capture hooks.
- **Upkeep:** on. Free maintenance runs while a gbrain session is open. `gbrain config set maintenance.auto false` turns it off.
- **Conversation archive:** on by default. It keeps one redacted page per conversation per day, and without an API key nothing leaves this machine. `gbrain transcripts archive off` turns it off.
- **Starter pages:** none added. `gbrain setup claude-code --shape personal` adds empty pages for facts about you, your voice and how you decide.
- **Release channel:** gbrain reports that this install follows the weekly stable channel, so future upgrades will come from there rather than staying on v0.60.734.0.

`gbrain doctor` scored 95/100. Its only warning says Claude Code has no gbrain registration, but `claude mcp get gbrain` shows it registered and connected. The check also notes it can't verify the registration from its own process, so I don't think there's a real problem.
