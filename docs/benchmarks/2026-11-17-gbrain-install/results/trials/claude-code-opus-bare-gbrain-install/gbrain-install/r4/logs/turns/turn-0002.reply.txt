gbrain is set up for Claude Code using the free defaults, with no API keys. I saved a test fact and recalled it, which worked. gbrain starts in your next Claude Code session, not this one, because Claude Code reads its config at startup.

**What setup did**
- Created a local brain at `~/.gbrain/brain.pglite` (`~` here is `/harness-state`). It has no embeddings, so search works by keyword only.
- Registered gbrain as an MCP server in Claude Code. `claude mcp get gbrain` reports it as **Connected**.
- Added two hooks to `/harness-state/claude/settings.json`: one runs at session start, one on each prompt.
- Created `/harness-state/claude/CLAUDE.md` with gbrain's instructions telling the agent to check the brain first.

**Settings now in effect (gbrain's defaults)**
- **Paid providers:** declined, so gbrain never calls a model provider on its own. Run `gbrain setup claude-code --providers` to allow it later.
- **Session capture:** off.
- **Saving facts:** only when you ask it to remember something. `salient` mode would save important facts you mention automatically; it's off unless you turn it on.
- **Search mode:** conservative. It's the only mode that works without a key.
- **Conversation archive:** on. gbrain keeps one redacted page per conversation per day from your agent sessions on this machine. Without an embedding key nothing leaves the machine. Turn it off with `gbrain transcripts archive off`.
- **Upkeep:** free maintenance runs while a gbrain session is open. Turn it off with `gbrain config set maintenance.auto false`.
- **Starter pages:** none. Run `gbrain setup claude-code --shape personal` if you want empty pages for facts about you, your voice and how you decide.

**Things to know**
- `gbrain doctor` scores 95/100. Its one warning says Claude Code has no gbrain MCP entry, but Claude Code shows the entry as connected. I left it alone rather than re-running setup with the flag the warning suggests. It may go away once a new session confirms the connection.
- Without embeddings, gbrain only catches exact duplicates when saving. A fact worded slightly differently is saved again.
- `~/.bun/bin` still isn't on your PATH in new shells. Add `export PATH="$HOME/.bun/bin:$PATH"` to your shell profile to run `gbrain` directly.
