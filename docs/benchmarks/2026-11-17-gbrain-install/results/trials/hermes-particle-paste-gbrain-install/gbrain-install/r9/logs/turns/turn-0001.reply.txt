Search mode — currently conservative (and why)
Init auto-picked it because there's no chat key and no reranker, so balanced/tokenmax couldn't rerank. The cost matrix, verbatim:

Estimated downstream input cost of the retrieved payload @ 10K queries/mo:

                  Haiku 5.5     Sonnet 5.5    Opus 5.5
                  ($0.10/M in)  ($2/M in)     ($4/M in)
  conservative    $4/mo         $80/mo        $160/mo
  balanced        $10/mo        $200/mo       $400/mo
  tokenmax        $20/mo        $400/mo       $800/mo

  Assumed payload per query: conservative 4K, balanced 10K, tokenmax 20K tokens.
  Scales linearly: x10 for 100K queries/mo, /10 for 1K. 200x corner-to-corner spread.
  Embedding, reranking and query expansion are separate provider charges.

  1) conservative — tight 4K budget, 10 chunks max, no reranker. Best for cost-sensitive setups.
  2) balanced — 12K budget, 25 chunks, reranked (needs an embedding provider).
  3) tokenmax — no budget, 50 chunks, reranked. Widest retrieval.

Swap any time: `gbrain config set search.mode balanced` (then `gbrain search modes` to confirm; I verified it reports active_mode correctly). Note these are downstream model input costs, not subscription prices.
