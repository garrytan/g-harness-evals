SEARCH-MODE CHOICE (yours to make; nothing waits on it)

In effect now: conservative — chosen because this brain is keyless (no chat key, no reranker).

Estimated downstream input cost of the retrieved payload @ 10K queries/mo:

                  Haiku 5.5     Sonnet 5.5    Opus 5.5
                  ($0.10/M in)  ($2/M in)     ($4/M in)
  conservative    $4/mo         $80/mo        $160/mo
  balanced        $10/mo        $200/mo       $400/mo
  tokenmax        $20/mo        $400/mo       $800/mo

  Assumed payload per query: conservative 4K, balanced 10K, tokenmax 20K tokens.
  Scales linearly: x10 for 100K queries/mo, /10 for 1K. 200x corner-to-corner spread.
  Embedding, reranking and query expansion are separate provider charges.

    1) conservative — tight 4K budget, 10 chunks max, no reranker. Best for cheap
       subagents and high-volume loops. (current)
    2) balanced — 12K budget, 25 chunks, reranked; needs a reranker key to actually rerank.
    3) tokenmax — no budget, 50 chunks, reranked; recommended once a chat key exists.

  Say the word and I run `gbrain config set search.mode <mode>` (plus
  `gbrain config set search.searchLimit 20` if you take tokenmax and want the old
  20-hit default). `gbrain query` doesn't expand by default in any mode.
