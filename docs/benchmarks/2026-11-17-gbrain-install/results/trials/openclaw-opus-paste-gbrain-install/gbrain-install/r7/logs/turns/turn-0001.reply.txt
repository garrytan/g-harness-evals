**Search mode, your choice.** Init set **conservative** because there's no chat key and no reranker. You can change it any time with `gbrain config set search.mode <mode>` and check it with `gbrain search modes`.

```
Estimated downstream input cost of the retrieved payload @ 10K queries/mo:

                  Haiku 5.5     Sonnet 5.5    Opus 5.5
                  ($0.10/M in)  ($2/M in)     ($4/M in)
  conservative    $4/mo         $80/mo        $160/mo
  balanced        $10/mo        $200/mo       $400/mo
  tokenmax        $20/mo        $400/mo       $800/mo

  Assumed payload per query: conservative 4K, balanced 10K, tokenmax 20K tokens.
  Scales linearly: x10 for 100K queries/mo, /10 for 1K. 200x corner-to-corner spread.
  Embedding, reranking and query expansion are separate provider charges.
```

1. **conservative** (in effect): 4K-token budget, at most 10 chunks, no reranker. Best for Haiku-class models, cost-sensitive setups and high-volume loops.
2. **balanced:** 12K budget, 25 chunks, reranked. The reranking needs a key, which you don't have yet.
3. **tokenmax:** no budget, 50 chunks, reranked. The widest retrieval; it's the recommended mode once you have a chat key.

No mode expands queries by default; `gbrain query --expand` forces it for one call. These figures estimate what your model pays to read the retrieved text, not your actual bill.

**Other settings in effect**
