gbrain 0.60.757.0 now has a working local brain, and it's free with no API keys.

- **Brain:** created at `~/.gbrain/brain.pglite`. It's a local database with no server and no API keys, so search works by keyword only.
- **Setup steps:** all five pending setup migrations ran and exited 0.
- **Health:** `gbrain doctor` scores 90/100 with no failures. The warnings come from having no embeddings and an empty brain, which is expected here.
- **Round trip:** I saved one test fact, "gbrain install check", and searching found it again.
- **PATH:** I created `~/.bashrc` (it didn't exist) with the Bun PATH line, so `gbrain` works in new shells.

Settings in effect (the free defaults):

- **Search mode:** conservative. It was picked automatically because there are no API keys. Change it with `gbrain config set search.mode balanced` or `tokenmax`.
- **Auto-saving facts:** off, so agents save only what you ask them to remember. The docs recommend `gbrain config set memory.auto_writeback salient` for a personal brain, but it's opt-in, so I left it off.
- **Free upkeep:** on. It only runs while an agent has a gbrain session open.
- **Conversation archive:** on. It keeps one redacted page per agent conversation per day, and with no API keys nothing leaves this machine. Turn it off with `gbrain transcripts archive off`.

I didn't connect gbrain to an agent. The obvious one here is Hermes, but gbrain's own setup says this step is for you to run, not an agent. It would change Hermes's own config, its `SOUL.md` and its per-turn hooks, which affects every session. I previewed it with `--dry-run` and it looks clean. To do it:

    gbrain setup hermes

Then start a new Hermes session. Use `gbrain setup claude-code` or `gbrain setup codex` instead if you use those, and `--remove` undoes it.

The test fact "gbrain install check" is still in the brain. It's harmless, but you can remove it whenever you like.
