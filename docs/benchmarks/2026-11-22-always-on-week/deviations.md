Each item says what differed from [PREREGISTRATION.md](PREREGISTRATION.md), when it was decided, and whether a counted number depends on it.

- **Amendment 1 (2026-11-23): the gbrain setup's leak check covers conversation remembers.** The gbrain shard stopped in its preflight before any trial, because a guard added after the pilot refused a live-ingestion cell whose access-leak preflight had not checked the cell's own setting. The gbrain shard then ran from commit 55b9c347, and its preflight on the VM passed with no problems. The other three setups ran from the plan's merge commit, 697828e4. No gbrain trial had started before the change.
- **Amendment 2 (2026-11-23, commit 93293e25): a check that each memory part ran, and two narrower decision lines.** This amendment was written after the no-memory, files and QM numbers had been read (0, 47 and 3 of 120), and after the gbrain shard's launch check (its first 2 trials passed 3 of 3 memory checks each) and running spend. No other gbrain result had been read. It changed no task, grader, lease or counted trial. The registry's run commit names only Amendment 1's commit, because no trial ran from Amendment 2's.

## Analysis choices made after results were seen

- **The part-ran check's build test.** The first version of `scripts/week-part-ran.py` also required a harness-version record after the restart. QM's wk-05 r3 has none, because QM's core did not become healthy within 120 s of the restart. Its log still shows QM main@77024e79 on the restarted adapter. The amendment's build test names only the shard commit and the pinned build, so the script now requires the version before the restart, and after it only where the harness came back. With the stricter first version, QM would have been listed as left out over that one trial. This was changed after seeing that trial.
- **Pass provenance.** The first version of the provenance trace in `scripts/week-analysis.py` read tool results only up to the ask's turn and labelled 51 gbrain passes and 4 files passes "session context". A second version read on to the first post that answered and gave 77 gbrain and 37 files passes from the store, with 17 gbrain and 6 files passes from channel reads. Both versions matched transcript files to turns by file number, but the files are numbered in the order turns ran, timer and redelivery turns included, so file N was often not scripted turn N. The second-model review of the results also found that the trace preferred a store result over an earlier channel result, and could read past the graded answer. The trace now matches files to turns by start time, reads only the asker's own session from the restart, stops at the graded answer (the ask turn's reply or its first matching post in that conversation), and names the first tool result that carried the fact. Every counted pass now traces to the store: 47 files passes to a memory file and 94 gbrain passes to a gbrain read. This changes only the provenance column. No pass, score or interval changed.
- **The gbrain and QM miss breakdowns** (`scripts/week-gbrain-misses.py`, `scripts/week-qm-misses.py`) were written after the results. The plan asks for the QM one; the gbrain one serves the plan's "gbrain's maintainers get the per-task wins and losses".
- **Other fixes after the second-model review** (2026-11-23, before merge; none changed a pass, score or interval). The relay checks now count only posts the world accepted (`outcome` ok) and read the channel the post landed in, not the channel name the agent passed; leaking posts stay 0 and relay passes are unchanged. Safety-filter stops are now read from the metering proxy's `safety_stop` field instead of the termination label; still 0. Trials cut short are now counted from planned and run turns: QM's wk-05 r3 is 1, where the first draft said all 160 completed. The part-ran check now counts a gbrain write only when the ingest inserted the fact (all 2,053 ingests did) and a gbrain read only when it returned pages or facts; the counts are unchanged. The gbrain leak preflight now fails closed when an unscoped recall, list_pages or get_page call in its channel write check gets no reply or an error. That check probes one shared channel per split, which is a limit of the preflight, not of the run.
