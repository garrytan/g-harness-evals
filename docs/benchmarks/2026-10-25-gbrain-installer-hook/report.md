## What gbrain should change, in the order the evidence supports

1. **Treat the revised installer (block v2 plus the hook) as the working one, and keep both parts until a run separates them.** The block alone at `99294fe4` moved use by nothing; the block v2 with the hook at `10949a15` puts a gbrain call in every trial of both harnesses, at about $0.002 and 50,000 to 55,000 input tokens more per trial than the preamble clause. gbrain#7489 at `10949a15` is still open; this run is evidence for it as a whole. A run with the block v2 and no hook would say which part does the work; this pair of runs does not.
2. **Decide what the block should say about `source_ids` on an unscoped surface.** Two of the OpenClaw installer cell's 232 calls followed the block's own instruction and passed `source_ids`, and gbrain refused them with `permission_denied` because the token's scope is `none`; the bot recovered on the next call. Either the block should say when `source_ids` applies, or an unscoped token should accept and ignore it. The other two errors are wrong values for `match` and `return_unit`, a model matter.
3. **The cross-scope read count did not move the same way in the two harnesses (15 to 29 rows on OpenClaw, 11 to 5 on Hermes).** Every row is a `channel` page returned under the bot's grant. The told-scoped run (`gbrain-scoped-2026-10`, gbrain#7481's per-request `source_ids`) is the preregistered test of whether scoping the search removes them; this run adds that the installer's extra calls can raise or lower the count depending on the harness.
