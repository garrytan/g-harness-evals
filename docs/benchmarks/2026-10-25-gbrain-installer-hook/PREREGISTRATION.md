# gbrain installer rung preregistration, second run: told against the installer with its per-turn hook, five repetitions

Status: written 2026-10-25 (UTC), before any trial of this run. Run id `gbrain-installer-hook-2026-10`. Cells are in [prereg.json](prereg.json); `bun runner/run.ts plan --prereg docs/benchmarks/2026-10-25-gbrain-installer-hook/prereg.json --out <dir>` prints 400 trials in 4 cells, a planning ceiling of $9.88 against the $8 cap (the ceiling is the per-trial token ceiling priced at list; the first installer run spent $0.80 and $1.19 per 100-trial `told` cell and $0.74 and $0.63 per `installer` cell, $3.36 in all, so the expected spend is about $3.50 and the cap is about twice it). The rung, the hook, the sidecar and the runner's handling of them are in [docs/gbrain-arm.md](../../gbrain-arm.md), "The installer rung" and "The per-turn hook".

## Why this run

The first installer run (`gbrain-installer-2026-10`, [../2026-10-25-gbrain-installer/report.md](../2026-10-25-gbrain-installer/report.md), merged as #73) found that gbrain's installer at `99294fe4` put its brain-first block into the harness's instruction file in every trial and that the bot then called gbrain in 0 of 80 primary-task trials on each harness, against 69 of 79 and 73 of 80 in the `told` cells (use installer minus told -87 points [-98, -74] and -91 [-100, -78]); the installer cells behaved like the ladder's `mcp` cells (use 2 of 99 and 0 of 100). The block sat in the system prompt or `SOUL.md`; the hand-written clause sits in the preamble that arrives with every turn. GBRA-188 revised gbrain#7489 after that report: `gbrain setup <harness> --instructions-only` still writes the file block (now v2) and also installs a per-turn rule through each harness's own extension point, an OpenClaw plugin whose `before_prompt_build` hook prepends the rule to every prompt, and a Hermes `pre_llm_call` shell hook that echoes the rule as context on every call. This run asks the first run's question again at the revised commit, with the runner's `installer` rung carrying the new outputs into the harness, so that the run measures the hook and not the old block a second time.

## Question

On the same 20 held-out multi-user tasks on Haiku, for OpenClaw and Hermes Agent, does gbrain's revised installer (`gbrain setup <harness> --instructions-only` at gbrain `10949a15`, an open unmerged pull request, the file block plus the per-turn hook) reproduce what the hand-written `told` clause does: gbrain use in nearly every trial; and does it leave pass rate and cross-scope reads via keyword search where `told` has them, at five repetitions per task.

## Design

Four cells, each 20 tasks by 5 repetitions (100 trials): for each of OpenClaw and Hermes on `anthropic:claude-haiku-5-5`, the ladder's `told` cell (`gbrain.surface` starter, MCP registration, keyword search, preamble `tasks/multiuser/_shared/preamble.gbrain-ladder.md`) and an `installer` cell (`gbrain.surface` starter, the same registration and search, `gbrain.install` `gbrain-installer`, the default preamble `tasks/multiuser/_shared/preamble.md` with no brain-first clause). The two cells of a pair differ in exactly where the brain-first instruction comes from: the eval's preamble, or what gbrain's installer wrote and installed. The cell ids are the first installer run's; the run id separates the receipts. The design, the endpoints and the decision sentence are the first run's unchanged, so the two runs read side by side.

## Endpoints

Primary: gbrain use (at least one gbrain tool call inside a turn window) over the 16 capable held-out tasks (families `scope_isolation`, `shared_channel`, `org_security`, `handoff`), 80 pairs per harness, the paired difference installer minus told, trial by trial (same task, same repetition index), with the exact sign-flip p over task clusters and a task-clustered paired bootstrap 95 percent interval (seed 7, 10,000 draws). One Holm family of two: the OpenClaw comparison and the Hermes comparison. The two harnesses are not compared with each other. Use in the installer cells is also reported against the ladder's `mcp` cells (2 of 99 and 0 of 100) and against the first installer run's installer cells (1 of 99 and 0 of 100) as between-run descriptive lines with no inference: `mcp` is what the installer cell would be if neither the block nor the hook were read, and the first run is the block alone.

Secondary, preregistered: pass over the same 16 tasks and 80 pairs, the same paired difference, interval and test, Holm over the same family of two, reported with its interval and the minimum detectable difference beside it and never as an equivalence claim; cross-scope reads via gbrain per cell, as the count of trials with at least one and the count of offending rows, with the paired difference and interval (the `told` cells showed 10 and 11 of 80 trials in the first run; an installer cell that searches as often as told is expected to show the same). Also descriptive: in how many trials of each installer cell the hook was loaded (`gbrain.install_bundle.turn_hook` and the per-trial `gbrain-hook.openclaw.json` and `gbrain-hook.hermes.log` receipts) and the file was in place (`install_bundle` in the record; for Hermes the committed `state/hermes/SOUL.md` receipt, whose sha256 is the seed followed by the block, since the adapter's own `replaced_seed` note sits in `logs/gbrain-install.json`, which is not a kept receipt); that status is the harness's own account before the first turn (OpenClaw's `plugins inspect --runtime`, Hermes's `hooks doctor`) that the hook is loaded, not a per-turn proof that it fired, so the keyless adapter test's finding (the rule in the first model request's messages, both harnesses) stands for that, and harness input tokens per trial, installer against told, are reported beside the status as the per-trial descriptive sign that the rule arrived; gbrain use per cell, calls per trial, tools called, pages per call, latency; pass over all 20 tasks; pass^5 and pass@5 per task; cost per trial and per success, harness input and output tokens; approval stops, consent violations and hidden-fact leaks as counts with trial ids; the ladder's, the verbs run's and the first installer run's `told` cells beside this run's as a between-run stability check with no inference.

Minimum detectable paired difference at this design, computed before this run with `bun scripts/paired-mdd.ts --ladder --results docs/benchmarks/2026-10-25-gbrain-installer/results --reps 5` (two-sided alpha 0.05, power 0.8, each task at the first installer run's measured `told` rate, cluster-robust standard error, n = 20 tasks by 5 repetitions): use 8.1 points at OpenClaw's told rate (90 percent) and 6.3 at Hermes's (92 percent); pass 12.1 and 9.3 points at told rates of 57 and 64 percent; cross-scope reads 9.3 points at OpenClaw's told rate (11 percent) and 5.7 at Hermes's (11 percent). The exact sign-flip test needs at least 6 task clusters moving the same way, and a task at 0 or 5 of 5 in both cells adds nothing to either test; 16 and 17 of the 20 tasks were at 0 or all of their repetitions on use in the first run's told cells, so the use test will rest on few clusters and the interval carries the result.

## Decision sentence

The installer is reported as reproducing the told clause's effect on use for a harness when the paired interval on use lies within 10 points of zero on both sides, with the Holm-adjusted p reported beside it; as not reproducing it when the interval excludes zero and the installer cell's use is below told's by more than 10 points; otherwise "not distinguished at 16 tasks by 5 repetitions", with the interval. Pass is reported as a paired difference with its interval and the minimum detectable difference, never as "the same". Cross-scope reads are reported as counts with intervals, not as a verdict. A trial whose installer did not take (no `gbrain.install_bundle` record in `trials.jsonl`, or `install_bundle.turn_hook.status` other than `loaded`/`healthy`; the adapter refuses a file not in place, a Hermes seed it cannot replace or a hook the harness does not report loaded or healthy with HE-ADAPTER-006 before ready, so such a trial is also `harness_error` and its status reads `no ready file`) leaves every paired endpoint with its pair, listed with its reason, the way a model or infra error does: `scripts/compare-run.ts` exclusion `installer_not_applied`, the pairs in `comparisons.gbrain.json` and their count in the report, split by cause from each excluded trial's `adapter.log` (an HE-ADAPTER-006 refusal, or another failure before ready such as a harness that never started, which in a told cell stays a scored `harness_error`; the two counts are reported side by side so the asymmetry is visible); no verdict from an incomplete pair. Every number in the report is tied to a receipt path.

Predictions, recorded so they can be wrong: after the smoke (10 of 10 installer trials per harness called gbrain with the hook loaded) the prediction is that use in the installer cells lands within 10 points of told's in both harnesses, so the installer is reported as reproducing the clause; that the installer cells make somewhat more gbrain calls per trial than told (the smoke saw 2.0 against 1.0), because the rule arrives on every turn; that pass in the installer cells sits within the minimum detectable difference of told's, with the interval through zero; that cross-scope reads in the installer cells are at or above told's 10 to 11 of 80, since the bots search at least as often, reported as counts; and that the hook is loaded and the file in place in every trial of both installer cells. If the held-out run shows use far below told's with the hook loaded, the dev-task smoke was too few trials or the held-out tasks differ, which is why the run exists.
