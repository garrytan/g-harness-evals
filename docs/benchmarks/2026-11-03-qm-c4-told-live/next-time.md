## Next time

### What we'd change if we ran this again

- Use told-fact tasks where QM's own notebook does not already hold the answer, and first check that the no-gbrain arm scores clearly below the top, because the no-gbrain arm passed all 20 continuity trials on both models, so neither gbrain route had room to show a gain.
- Give the corrections tasks a direct-message turn when the memory provider is under test, because QM runs its provider only in direct messages and the 4 corrections tasks had none, so the provider never ran on the one family with headroom.
- Pin a QM build whose memory provider works as shipped, because at the pinned build every provider recall was refused for an over-long question and QM hid the refusal, so every memory-provider figure needed a question trim in our proxy.

### Ideas to improve the eval

- Check every exposure figure against the script that computes it before the report goes out, because the notebook count has to stop where QM's injected gbrain block starts, and on that rule Sol's memory-provider figure is 6 of 20.
- Capture each consumer turn's model request in QM cells, because without it the run could not tell whether session history also carried the told fact.
