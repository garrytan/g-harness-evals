gbrain#7744 (internal-task, "search: saved facts match stemmed whole words; correction-cue ordering behind search.saved_facts_supersede (default on)") changes how `search` picks the saved facts it returns beside its rows: words now match whole after stemming with the brain's full-text language (so "renewal" matches "renews" and "count" no longer matches inside "countersigned"), and, with `search.saved_facts_supersede` on (its default), a newer fact carrying a correction cue that shares at least two matched words with a returned fact is returned even below the three-quarter threshold, ahead of the fact it corrects, which carries `corrected_by`. Its head at this pin, `81692dc6`, is two commits after `0c568a61`, the head this preregistration was first drafted against. `7ff7cbb5` stopped question-framing words (count, number, total, amount and the like) from counting toward the saved-facts match threshold and returns every correction of a returned fact, not only the newest. `81692dc6` ("search: saved facts need at most four of a question's words; replies that report a correction or restate it on a named date correct nothing") makes a fact need at most four of the query's words, stops "corrected" and "correcting" from counting as correction cues, and stops day-month dates from counting as figures. The pull request's own keyless replay of every `search` call of the memory run (816 calls across 443 live trials, against the facts each trial had ingested by then, under the member grant) reports the author's `cr-05` correction returned above the retracted post in 27 of 27 searches, 13 of 13 on Sonnet, with the flag on (at its head `81692dc6`), against 1 of 27 and 0 of 13 on master (0 of 27 with the flag off); that replay is gbrain's measurement, not a receipt of this repository. This run asks whether that change reaches what the harnesses pass.

## What the run measures and what it cannot say

Within the run, a `gbrain-told-live` cell differs from its `none` cell in the same three things as in the memory run: the sidecar registered as a second MCP server, the brain filling with the scenario's messages, and preamble rule 7. The brain holds nothing the bot could not read through the world tools, so a pass difference is a memory and retrieval difference.

Between runs, this run's live cells differ from the memory run's live cells in the gbrain commit (`b06ac32b` to `81692dc6`: 191 master commits and gbrain#7744's eight), the proxy and bind changes of the planned amendment, the day, the VMs and nothing else this repository controls. A difference between the two runs' live cells on a task therefore cannot be assigned to gbrain#7744 alone, and the two runs' `none` cells, which also differ in the proxy and bind changes, the day and the VMs, measure how far two runs of the same cell drift (the memory run's none cells passed 53, 47 and 36 of 75 on Sonnet against v02-heldout's 42, 50 and 38). The between-run comparison is descriptive and has no pairing: repetition r1 of one run has nothing in common with r1 of the other.

The primary endpoint cannot reach the preregistered bar for a difference unless a ceiling task moves. With 8 task clusters, the exact two-sided sign-flip test reaches 0.05 only when at least six clusters move one way (2/2^6 = 0.031; [paired-mdd.md](../2026-10-26-gbrain-memory/results/paired-mdd.md)). A cluster whose pairs all tie adds nothing, and four of the eight tasks (`cn-07`, `cr-06`, `cr-07`, `cr-08`) were 5 of 5 in every Sonnet cell of the memory run. If they hold, at most four clusters can move, the smallest attainable two-sided p is 2/2^4 = 0.125, and every Holm-adjusted p is at least that. The primary is kept as the memory run stated it so the two runs read alike, and it is expected to read "not distinguished at this size" whatever the fix does. What this run can show is the per-task movement on `cr-05` and the mechanism beside it (the correction returned to the harness), both descriptive.

## Decision sentences

- The primary endpoint is read per harness and model from the Holm-adjusted p and the interval: an interval excluding zero with adjusted p below 0.05 is a difference; anything else is "not distinguished at this size", with the achieved MDD and the smallest attainable sign-flip p beside it. Intervals, never ranks. The Sonnet family carries the conclusion; the Haiku family is the sensitivity half and never carries a headline on its own.
- The fix is reported as reaching the harnesses on `cr-05` only in the words the counts support: the live cells' passes of 5 beside the none cells' and beside the memory run's, and the mechanism count beside them, never as a tested effect. A `cr-05` movement in the live cells with no movement in the mechanism count (the correction not returned) is reported as not attributable to the brain, except on Hermes, where a pass with no recorded correction is reported as unattributed (the correction may have come through the unrecorded hot-memory block), with the hot-memory reconstruction used for the memory run (`results/hot-memory-blocks.json`) beside it where it applies.
- A live cell with any cross-scope read through an ingested fact is reported in its first section as a scope finding (the grant, the tap or the grader, named with the event), in the same breath as any pass gain; the finding goes to gbrain through the Captain when it is gbrain's.
- A live cell with three or more HE-GBRAIN-011 exam faults is reported with those faults as its first caveat; if they are an ingestion defect rather than a sidecar outage, the cell is rerun under a new run id after the fix, and the partial cell is published as partial.
- A harness with three or more `harness_error` or `infra_error` trials in a cell gets a fix and a rerun of that cell under a new run id; its partial cell is published as partial.
- A shard that reaches its lease stops under `--stop-on-cap`; its cell is published as partial with the trials it completed, in the preregistered task order, and the report says so in its first section. Leases are not moved between shards after a cell starts.
- If gbrain#7744 merges, changes or closes while the run is in flight, nothing changes for this run: it ran `81692dc6`, and the report names the pull request's state on the day it is written.
- Any deviation that needs a decision (a cap that would be exceeded before a cell completes, a shard that cannot be resumed at the recorded commit, an image that fails preflight after the run has begun elsewhere, paid spend approaching $100 of the $120 lane) stops the affected shard and goes to the Captain; everything else is recorded in the report's deviations section.
