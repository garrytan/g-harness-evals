## Next time

### What we'd change if we ran this again

- Score the plain plan replies against the rubric's band as soon as the headroom check ends, because plain plans fell below the band (Opus 2 of 24, Sol 0 of 24) only after both judges were calibrated, and the plan tasks then left the run on a trigger the preregistration did not list.
- Build the files the VM setup downloads into the image or a mirror, because GitHub 504 errors failed seven canary launches before any trial and moved every counted trial to a later commit than planned.
- Copy the forced stage's results into folders of its own, because they overwrote the main stage's backup copy and the main results had to be restored from the controller's copy.

### Ideas to improve the eval

- Preregister finding the defect and flagging a decoy as outcomes beside the pass rule, because the skill found the planted bug a little more often but raised more false alarms, and only the combined pass counted.
- Run the forced arm at more than one try per task, because at one try per task and model it is descriptive only, yet it was the run's one clear effect.
