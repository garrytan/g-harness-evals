# gbrain installer rung preregistration: told against installer at five repetitions

Status: written 2026-10-25 (UTC), before any trial of this run. Run id `gbrain-installer-2026-10`. Cells are in [prereg.json](prereg.json); `bun runner/run.ts plan --prereg docs/benchmarks/2026-10-25-gbrain-installer/prereg.json --out <dir>` prints 400 trials in 4 cells, a planning ceiling of $9.88 against the $8 cap (the ceiling is the per-trial token ceiling priced at list; the verbs run's measured spend on the `told` rung was $0.0079 per trial on OpenClaw and $0.0083 on Hermes, so the expected spend is about $3.20 and the cap is about two and a half times it). The rung, the sidecar and the runner's handling of it are in [docs/gbrain-arm.md](../../gbrain-arm.md), "The install ladder (HARN-5)" and "The installer rung".

## Why this run

The install ladder (run `gbrain-ladder-2026-10`, [../2026-10-25-gbrain-ladder/report.md](../2026-10-25-gbrain-ladder/report.md)) found that registering gbrain's MCP server produced no use (2 of 99 and 0 of 100 trials), that gbrain's documented install bundle produced none either (0 of 100 and 1 of 100), and that one clause in the bot's instructions (`told`) turned use on in 90 and 94 percent of trials. gbrain#7489 (GBRA-188) is gbrain's answer: `gbrain setup <harness> --instructions-only` writes a brain-first instruction block into the file the harness reads on every turn (OpenClaw's workspace `AGENTS.md`, Hermes's `SOUL.md`). This run asks whether the product's own installer reproduces what the hand-written clause did, with the eval's unchanged preamble, on the same held-out tasks. The runner's `installer` rung (#68) applies the bundle gbrain's installer wrote at image build; this preregistration is the first counted use of it.

## Question

On the same 20 held-out multi-user tasks on Haiku, for OpenClaw and Hermes Agent, does gbrain's own installer (`gbrain setup <harness> --instructions-only` at gbrain `99294fe4`, an open unmerged pull request) reproduce what the hand-written `told` clause does: gbrain use in nearly every trial; and does it leave pass rate and cross-scope reads via keyword search where `told` has them, at five repetitions per task.

## Design

Four cells, each 20 tasks by 5 repetitions (100 trials): for each of OpenClaw and Hermes on `anthropic:claude-haiku-5-5`, the ladder's `told` cell (`gbrain.surface` starter, MCP registration, keyword search, preamble `tasks/multiuser/_shared/preamble.gbrain-ladder.md`) and an `installer` cell (`gbrain.surface` starter, the same registration and search, `gbrain.install` `gbrain-installer`, the default preamble `tasks/multiuser/_shared/preamble.md` with no brain-first clause, the one the ladder's `mcp` and `docs` cells ran with). The two cells of a pair differ in exactly where the brain-first instruction comes from: the eval's preamble, or the file gbrain's installer wrote. The `told` cell ids are the ladder's and the verbs run's; the run id separates the receipts.

**Why five repetitions and not ten.** The question is use, and a failed installer looks like the `mcp` rung: use in 1 to 2 percent of trials against `told`'s 86 to 94. At 20 tasks by 5 repetitions the minimum detectable paired difference on use, computed from the verbs run's `told` cells with `bun scripts/paired-mdd.ts --ladder --results docs/benchmarks/2026-10-25-gbrain-verbs/results --reps 5`, is 8.0 points for OpenClaw and 4.7 for Hermes (5.7 and 3.3 at ten), far below the effect a failure would show. Pass is where repetitions would buy precision, and the verbs run just showed that even ten repetitions leave an 8 to 9 point pass difference unresolved (minimum detectable 8.1 and 6.9 points at ten, 11.5 and 9.7 at five); an installer whose block carries the same instruction as the clause is expected to move pass by about nothing, which neither design can distinguish from a small effect, so pass is a secondary endpoint here with its interval and not a verdict. Ten repetitions would also put the expected $6.40 against the $8 cap with each $2 lease at 80 percent, and a lease reached stops a cell incomplete and decides nothing.

The smoke proves the recipe end to end and changes the prediction below; it does not change the design, since the question is exactly whether the installer's block does what the clause does on the held-out tasks, with intervals.

## Endpoints

Primary: gbrain use (at least one gbrain tool call inside a turn window) over the 16 capable held-out tasks (families `scope_isolation`, `shared_channel`, `org_security`, `handoff`), 80 pairs per harness, the paired difference installer minus told, trial by trial (same task, same repetition index), with the exact sign-flip p over task clusters and a task-clustered paired bootstrap 95 percent interval (seed 7, 10,000 draws). One Holm family of two: the OpenClaw comparison and the Hermes comparison. The two harnesses are not compared with each other. Use in the installer cells is also reported against the ladder's `mcp` cells as a between-run descriptive line with no inference, since `mcp` is what the installer cell would be if the block were not read.

Secondary, preregistered: pass over the same 16 tasks and 80 pairs, the same paired difference, interval and test, Holm over the same family of two, reported with its interval and the minimum detectable difference beside it and never as an equivalence claim; cross-scope reads via gbrain per cell, as the count of trials with at least one and the count of offending rows, with the paired difference and interval (the `told` cells showed 10 and 11 percent of trials in the verbs run; the installer cells use the same keyword `search`, so the question is whether the block changes how often the bot searches into channels the requester is not in). Also descriptive: in how many trials of each installer cell the installer's file was in place (`gbrain.install_bundle`, and `replaced_seed` for Hermes); gbrain use per cell, calls per trial, tools called, pages per call, latency; pass over all 20 tasks; pass^5 and pass@5 per task; cost per trial and per success, harness input and output tokens; approval stops, consent violations and hidden-fact leaks as counts with trial ids; the ladder's and the verbs run's `told` cells beside this run's as a between-run stability check with no inference.

Minimum detectable paired difference at this design, computed before this run with `bun scripts/paired-mdd.ts --ladder --results docs/benchmarks/2026-10-25-gbrain-verbs/results --reps 5` (two-sided alpha 0.05, power 0.8, each task at the verbs run's measured `told` rate, cluster-robust standard error, n = 20 tasks by 5 repetitions): use 8.0 points at OpenClaw's told rate (89 percent) and 4.7 at Hermes's (95 percent); pass 11.5 and 9.7 points at told rates of 57 and 65 percent; cross-scope reads 7.4 points at OpenClaw's told rate (10 percent) and 7.0 at Hermes's (11 percent). The exact sign-flip test needs at least 6 task clusters moving the same way, and a task at 0 or 5 of 5 in both cells adds nothing to either test; 15 to 17 of the 20 tasks were at 0 or all of their repetitions on use in the verbs run's told cells, so the use test will rest on few clusters and the interval carries the result.

## Decision sentence

The installer is reported as reproducing the told clause's effect on use for a harness when the paired interval on use lies within 10 points of zero on both sides, with the Holm-adjusted p reported beside it; as not reproducing it when the interval excludes zero and the installer cell's use is below told's by more than 10 points; otherwise "not distinguished at 16 tasks by 5 repetitions", with the interval. Pass is reported as a paired difference with its interval and the minimum detectable difference, never as "the same". Cross-scope reads are reported as counts with intervals, not as a verdict. A trial whose installer file was not in place (no `install_bundle` record or a Hermes seed not replaced) is excluded from the installer cell's primary endpoint, listed with its reason, and the endpoint is recomputed without its pair as a labelled line; no verdict from an incomplete pair. Every number in the report is tied to a receipt path.

Predictions, recorded so they can be wrong: before the smoke the expectation was that use in the installer cells would land within 10 points of told's, since the block carries the same instruction and the adapter tests saw it in each harness's system prompt; after the smoke (1 of 10 trials per harness called gbrain with the block in place) the prediction is that use in the installer cells stays below 20 percent in both harnesses, near the ladder's `mcp` rung (2 and 0 percent) and far below told's 86 to 94, so the installer is reported as not reproducing the clause; that pass in the installer cells sits where the ladder's `mcp` and `told` cells both sat, with the paired difference's interval through zero; that cross-scope reads in the installer cells are near zero because the bot rarely searches at all; and that the installer file is in place in every trial of both installer cells. If the held-out run contradicts the smoke, the smoke's ten trials per harness were too few, which is why the run exists.
