# Error codes

Every runner, proxy and adapter failure prints one line that starts with its code, says what happened with the values involved, and ends with the fix command or the human prerequisite. Codes are stable; add a row here in the same commit that introduces one. Areas: PREREG, PIN, RUN, BUDGET, PROXY, ADAPTER, EGRESS, SCORE, TASK, PUBLISH, HELDOUT, LANEB, BRAIN, ZERO.

| HE-MODEL-001 | a trial's proxy usage names a model other than the cell's: a forwarded request in `usage.by_model`, or a refused line that carries a model (the allowlist refusal); the trial is `model_error` and the message lists the models. Refused lines with no model (a route the proxy does not admit) are counted in `usage.refused` and never fail a trial. QM's auxiliary requests are `claude-haiku-5-5`, so on a Haiku cell they are the cell's model; a non-Haiku QM or OpenClaw cell preregisters the allowance as the cell's `utility_models` (provider:model ids), which this check treats as the cell's own while the proxy forwards and prices them when the run's allowlist admits them (amendment 2 to `v02-heldout-2026-10`) | check the harness's model mapping (QM's `claude` harness, removed at QM `b6786d67`, fell back to its default model in silence when `CLAUDE_MODEL` was unsupported, `src/harness/claude-harness.ts` at `v0.1.15`) or fix the cell | runner/trial/trial.ts |
| HE-MODEL-002 | internal-task plan decision 12, Particle cells only: the proxy's usage lines decide the trial's termination, not the adapter's exit, because no adapter sees Particle's `error.code`. A Particle answer of HTTP 400 with `error.code` `invalid_value` or `unsupported_parameter`, or any HTTP 402, makes the trial `model_error`, which leaves the scored rows and is counted. Any other 400 keeps the exit classification (OpenClaw and Hermes exit 2, so `harness_error`), and an exit 3 on such a trial (QM maps every provider error to 3) becomes `harness_error`, unless the trial also logged a 429, a 5xx or a failed request on any provider, which could have caused the exit. A 429, a 5xx, the proxy's own refusals and an `exam_fault` leave the classification as it is, and a cap stop, a foreign model (HE-MODEL-001) or an infra failure still win. Only lines from the current attempt count, so a `--resume` rerun ignores lines its interrupted attempt left. It applies to multi-user, hello and smoke cells. The message names the status and code | read the trial's usage lines (`status`, `error_code`, `error_type`): a listed 400 means the request asked for something Particle-1 refuses (fix the harness's Particle template or the cell); a 402 means the Particle account is out of credit | runner/trial/trial.ts |

## Held-out openings

`bun runner/run.ts plan` and `dry-run` refuse a run with held-out cells before writing anything. The opening counter is `runner/heldout/openings.ts`; the ledger is the openings block of the set's `MANIFEST.json` ([methodology](methodology.md), item 13). A run's own ledger row passes every time it is planned while the row is `opened` or the set is `open` (CI refuses a planned confirmatory row on a set that is not open), so shard planning and `--resume` of the same run id are not refused. A preregistration committed before the openings ledger existed, whose `prereg.json` digest is in `runner/heldout/legacy-preregistrations.json`, is matched to its backfilled row and none of these codes applies to it; a dated amendment to such a preregistration adds the new digest to its entry in the same pull request. `bun runner/prereg/prereg.ts` (CI, on every pull request and every push to main) reports the same conditions over the whole registry as `heldout-openings:` lines.

## Replication (internal-task)

`bun runner/run.ts plan|dry-run --replication-of <run id> --cells <id,id> --reps <n> --run-id <new id> [--out <dir>]` plans named cells of a past held-out run again, from that run's registered `prereg.json`, under a new run id. It is not an opening: it writes no openings-ledger row and changes nothing under `tasks/`, so it runs only on a held-out set whose content is already public. The manifest records `replication_of` (`run_id`, `prereg_path`, `prereg_sha256`, `cells`, `reps`). `preflight` and `run` take the manifest like any other. Runs planned with `--prereg` are checked as before (HE-HELDOUT-001 to 004).

`scripts/replicate.ts` (docs/replicate.md) checks a finding from its trial bundle: `--reanalyze` and `--estimate-only` for free, or a paid rerun of one cell under `--max-usd` that ends in WITHIN BAND (exit 0), OUTSIDE BAND (4), NO BAND (5), INCOMPLETE (3) or a refusal (2). Every refusal prints its code, the safe actual value and a fix line; HE-BUNDLE codes come from the bundle check.
