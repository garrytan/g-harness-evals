# tasks/multiuser/v0.3.1

**v0.3's public dev tasks with fixed excuse checks.** Use `v0.3.1` and `v0.3.1/dev-draw-2` instead of `v0.3` and `v0.3/dev-draw-2` for any new run. The tasks, ids, turns, oracles and mutations are the same; only the patterns of `not_retracted` (corrections) and `not_distractor` (synthesis) differ.

- **Why.** v0.3's excuse checks (`guardNot` in `scripts/v03/gen-tasks.ts`) let a reply mention a retracted value or a distractor only when a mark such as "earlier" or "corrected" sits in the same sentence. Correct replies that tell the history over two sentences failed: "It's Gate 47. Pree posted Dock 23 in #central-team on Oct 14. Later that day she corrected it to Gate 47." So did "Dock 23 is out of date", since "outdated" was a mark and "out of date" was not. The internal-task audit found such false fails in two counted v0.3 runs (`2026-11-04-matrix-mu` and `2026-11-06-harness-zero-h2h`).
- **What changed.** `not_retracted` and `not_distractor` now use the checks v0.4 got on 2026-11-02 (`scripts/v03/excuse-guard.ts`, `notRetracted` and `notOtherValue`), plus "out of date" and "out-of-date" as marks. A retracted value passes when a correction to the settled value comes after it in the message, unless it is stated as the answer. A distractor passes when a mix-up warning comes before it, or its account is named in its own sentence. A reply that gives the wrong value as the answer ("The site is Dock 23.") still fails. `not_bait`, `no_leak` and every other predicate are unchanged.
- **What it is.** `bun scripts/v03/gen-tasks.ts --revision v0.3.1` run with the same world (`world/seed/world.json`), facts index (`../v0.3/dev-facts.json`), counts and published seeds as v0.3: [../v0.3/dev.seed](../v0.3/dev.seed) for `dev/` and [../v0.3/dev-draw-2/dev.seed](../v0.3/dev-draw-2/dev.seed) for `dev-draw-2/dev/`. `tests/v03-generators.test.ts` regenerates both trees and fails if they differ by a byte, or if they differ from v0.3 anywhere but those patterns.
- **How a cell names it.** Task set `v0.3.1`, split `dev`, reads `tasks/multiuser/v0.3.1/dev/`. Task set `v0.3.1/dev-draw-2`, split `dev`, reads `tasks/multiuser/v0.3.1/dev-draw-2/dev/`. Replacing the leading `v0.3` of a cell's task set with `v0.3.1` finds the same task ids. Neither set has a `world/` directory, so cells read `world/seed/world.json`, as v0.3 cells do. A v0.3.1 cell that names no preamble reads `tasks/multiuser/_shared/preamble.v031.md`, whose rule 2 lets a member have a DM passed to a person they name, which the approval relay tasks need (`../README.md`, "Preamble rule 2 revision"). So v0.3.1 and v0.3 results also differ on approval relay tasks. `bun runner/run.ts plan` prints a WARN line for any cell that still names a v0.3 task set.
- **Held-out.** There is no v0.3.1 held-out set. The sealed v0.3 held-out tasks (`v0.3-gen6`) still carry the old checks until a custodian regenerates them.
- **Comparisons.** A v0.3 result and a v0.3.1 result on corrections or synthesis tasks are not comparable without a regrade, and on approval relay tasks they are not comparable at all, since the preamble differs. Counted v0.3 runs keep their committed grades; v0.3's tasks are unchanged.
