# harness-evals

**Which AI agent harness gets the most out of a frontier model, and what does each solved task cost?** A harness is everything around the model (system prompt, tools, memory), such as Claude Code, Codex, OpenClaw, Hermes Agent or QM; we hold the model and tasks fixed, change one thing, and report what moved, including when our own add-ons, gstack and gbrain, don't help.

## What we found

All of these ran on Opus 5.5 or GPT-6.1 Sol. Most are dev results on public tasks, so they tell you what to try first, not what holds on every task.

- **We learned that agents obey a rule they see on every turn, and can ignore a skill file nobody mentions. You should put must-follow rules in a per-turn hook or the system prompt.** On GPT-6.1 Sol, a "check gbrain first" rule in a per-turn hook, the system prompt or the startup file was followed in 30 of 30 turns on Codex, Hermes and OpenClaw, against 4 to 6 of 30 with no rule. As an unmentioned skill it did nothing on Hermes or Claude Code. Caveat: 10 public tasks, one repetition; following the rule cost 10% to 55% more per turn, and with no access rules on the brain, more gbrain searches also meant more reads the asker wasn't allowed to see (12 trials) ([finding](findings/rule-placement/README.md)).
- **We learned that with the model fixed, we couldn't tell harnesses apart on how often they solved our tasks, but one cost about twice as much per solved task. You should compare harnesses on cost per solved task, on your own work.** Every harness passed 71.3% to 78.8%. On Opus, OpenClaw paid $0.44 per solved task against $0.19 to $0.24 for Claude Code, Hermes and QM. Against Claude Code, about 81% of OpenClaw's extra cost per trial was cache writes: it re-sends a much bigger system prompt and bigger tool results. Caveat: these tasks are too easy to separate harnesses, so a pass-rate gap under 7.7 to 14.2 points could hide here ([finding](findings/harness-cost/README.md)).
- **We learned that a shared brain leaks unless every read is scoped to the person asking. You should give gbrain, or any shared agent memory, per-person access rules.** With one bot-wide token, gbrain reads returned records the asker wasn't allowed to see in 33, 20, 17 and 9 of 51 trials across four cells. With per-member access rules on, that was 0 of 51 in all four, and Claude Code with gbrain passed 49 and 50 of 51 instead of 31 and 27. Caveat: 17 public tasks, and the gains over no brain are descriptive, with every interval reaching zero ([finding](findings/shared-brain-access/README.md)).
- **We learned that a prompt cut that looks free on easy tasks can break a harness on hard ones. You should test any prompt trim on tasks the agent can fail.** On easy tasks, dropping Claude Code's memory-and-skills text cut cost per trial by 19% with no measurable change in pass rate. On harder tasks, dropping it together with the advice in its tool descriptions took Claude Code from 60.4% to 0.0% (-60.4 points [-79.2, -39.6]). Caveat: the two parts were cut together, so the loss can't be pinned on one ([finding](findings/prompt-cuts/README.md)).

## Which harness should I use?

**20 public v0.3 multi-user dev tasks** (dev): **Saturated task set.** On these tasks pass rate can't separate the harnesses: 14 of 20 tasks scored the same in every cell, and this run had less than an 80% chance to detect a gap smaller than 7.7 to 14.2 points (9.5 to 17.6 at the first Holm step). What it does show is cost: OpenClaw on Opus paid about twice as much per pass as the other Opus harnesses (descriptive, no test).

- **Opus 5.5:** 3 preregistered pairs: 3 can't tell apart.
- **GPT-6.1 Sol:** 3 preregistered pairs: 3 can't tell apart.
