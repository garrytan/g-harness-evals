## [0.0.109] - 2026-11-02

### internal-task: the merge lane lands through gstack land, so pull requests stop renumbering

- **Pull requests no longer carry a version.** `.gstack/ship-policy.json` turns on `changelog_fragments` (dir `changelog.d`). A pull request adds a `changelog.d/<slug>.md` fragment, and gstack's `land` stamps VERSION, package.json and CHANGELOG.md at merge, so nobody re-ships just to renumber after another merge. `changelog.d/README.md` is the author side.
- `scripts/ubicloud/merge-pass.sh --land` (or `HE_LAND=1`): after every existing check, a receipted head is fetched from its pull request ref, made READY on a detached checkout (`gstack-pregate run`, then `gstack-ship-queue ready`, with the API key variables unset) and stamped with `land --no-wait`. A later pass merges the stamp only when its parents are the receipted pin and the base tip, `gstack-tree-receipt` says `same-modulo-stamps`, and every check is green at the stamp. A stamp of a base tip that has moved since is restamped from its pin.
- Fork pull requests are skipped under `--land` before any of their code is fetched or run. A land that returns without merging is a skip and writes no merge-log line, and a failed land is reported as a merge failure, so `pr-watch.sh` wakes the lane.
- Known gap, and the first item of internal-task's next lane PR. A stale stamp that GitHub does not report CLEAN (BEHIND or DIRTY) is skipped before the restamp step, so it needs `land --pr <n>` or `--repair` by hand. It fails closed and never merges a wrong tree.
- Docs: `scripts/ubicloud/README.md` and `docs/ubicloud.md`. Tests: `tests/merge-pass.test.ts` adds a `--land` block (the pin, the stamp, a moved base, a pin only its pull request ref reaches, a fork, a pending and a failed land) and an R65 no-panel receipt test.

### internal-task: compare-backups counts by task.toml family and checks a manifest commit (internal-task)

- `scripts/sealed/compare-backups.ts` `--family-field`: a task's family is the top-level `family` key of its `task.toml`, not its id prefix. Use it when task ids are opaque and share one prefix. ### internal-task: every Ubicloud VM carries a TTL in its name

- `scripts/ubicloud/ubi-runner.sh`: every VM it creates is named `ubirun-<owner>-<epoch>-<suffix>-t<hours>`, the encoding gstack's runner writes (gstack#3652). gstack's reaper destroys a VM once its epoch plus that many hours plus ten minutes has passed, whoever owns it, and sweeps names with no TTL after 4 hours. An inherited value is kept when it outlives `--timeout-hours` and refused (exit 2) otherwise. `--timeout-hours` must be a whole number from 1 to 998. `fanout.sh` goes through it. The poll stops the shard half an hour before a VM's TTL ends, whatever `--timeout-hours` says, so an `--attach` after a long sleep still copies the results back before the reaper can destroy the VM.

## [0.0.20] - 2026-10-28

### internal-task: the metering proxy binds the bridge gateway, requires bound slots and per-trial tokens, and lane VMs are firewalled

- `runner/trial/world.ts`: `containerHostAddress()` reads the docker default bridge gateway (`docker network inspect bridge`, 172.17.0.1 unless the daemon says otherwise; `HE_CONTAINER_HOST_IP` overrides it) and `listenHost(reachable)` returns the loopback or that address, never 0.0.0.0; a missing or wildcard address is HE-PROXY-004 (`docs/errors.md`). The world server and the metering proxy bind that address, so a container on the default bridge or a per-trial network reaches them as `host.docker.internal` and nothing outside the machine can. `MeteringProxy.start()` throws on a wildcard listen address and `--listen 0.0.0.0` exits 2.
- `runner/proxy/metering-proxy.ts`: in lease mode a provider request is forwarded only for a bound slot, and a slot bound with a token only when the request presents that token as `x-api-key` or a bearer; both refusals are 403, logged as refused under `slot:<id>` (never under a trial's meter, so an unauthenticated request cannot move a counted trial's numbers) and never reach the upstream. `isWildcardHost` canonicalizes the address, so `0`, `0.0`, `00.0.0.0` and `::0` are refused like `0.0.0.0`, and `containerHostAddress` accepts only an address the URL parser leaves unchanged. `POST /__proxy/bind` takes `token`; `ProxyControl.bind` passes it. Attribution is unchanged: `trialKey(id)` stays the meter id in every receipt.
- `runner/trial/proxy.ts` `trialToken(id)` is the random per-trial secret (`trial-token:<id>.<32 hex>`, no provider key shape). `runner/trial/trial.ts` and `runner/run.ts` bind the trial slot with it (unbound in the trial's `finally`, so the token dies with the trial on every exit) and hand it to the harness as `HE_MODEL_API_KEY` / `--api-key` (the compose override under the trial directory carries it; the results `.gitignore` excludes that file). The gbrain sidecar slot (`<slot>.gbrain`, the same trial key) is bound only when the cell's `gbrain.embeddings` is on, with its own token: `runner/trial/gbrain.ts` passes it as `HE_GBRAIN_PROXY_TOKEN` (an embedded brain without one is HE-GBRAIN-002) and `gbrain/entrypoint.sh` hands it to gbrain as `OPENAI_API_KEY`, refusing any value not shaped `trial-token:*`, with `GBRAIN_MODEL_DISCOVERY=off` so gbrain sends no `GET /v1/models` through the slot; the provider-key refusal is unchanged.
